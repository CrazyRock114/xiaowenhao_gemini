# 互动百科系统设计 & 第一期落地方案

## 一、项目定位

面向三年级和五年级两个孩子的**问题驱动式互动百科**：每期一个主题，以交互式网页呈现；孩子的开放问题被持续收集、沉淀为知识点，知识点之间建立关联，逐步生长成一张属于孩子自己的知识地图。

**核心闭环**（系统的灵魂）：
> 每期主题（互动探索）→ 孩子冒出新问题 → 问题箱收集 → 家长整理：解答/沉淀为知识点/催生下一期 → 知识地图生长 → 引出下一期

## 二、系统设计

### 2.1 数据模型（三大实体 + 孩子档案）

```
Issue（期）      { id, no, slug, title, subtitle, domain, date, cover,
                   blocks[], quiz[], experiments[], knowledgePointIds[], status }
Question（问题） { id, text, kid, date, status: 收集|已解答|已入期,
                   sourceIssue?, relatedKnowledge?, answer? }
KnowledgePoint   { id, name, domain, summary, explain: { basic, advanced },
                   relatedPointIds[], sourceQuestionIds[], issueIds[] }
KidProfile（孩子）{ name, grade, avatar, stars, completedIssues[], badges }
                   → localStorage，两个孩子档案互相独立
```

知识点与问题、期互相引用，这就是"问题之间关联、知识系统化"的数据基础。所有内容为**结构化 JSON 文件**（配 JSON Schema 校验），是可迁移的核心资产——后续与你自己的项目融合时，换一层渲染即可。

### 2.2 内容架构：内容即数据 + 分层阅读

- 每期 = `content/issues/001-xxx/` 目录：`index.json`（元数据+内容块序列）+ `quiz.json` + `assets/`
- **分层阅读**：知识点解释、问答卡答案、测验题都带 `basic`（三年级）/`advanced`（五年级）双档。孩子档案记录年级，页面按档过滤；页内提供"进阶内容"开关，默认基础、可展开进阶。

### 2.3 互动内容块引擎（可复用组件库，互动性的核心）

期内容 = 有序的**内容块（Block）**序列，V1 内置：

| 块 | 交互 |
|---|---|
| `hero` / `story` | 主题封面、故事化图文引入 |
| `qa-card` | 问答卡：问题在上，点击揭晓答案（可配图、分层答案） |
| `quiz` | 选择/判断题，即时反馈 + 得星星 |
| `match` / `sort` | 拖拽配对（术语↔解释）、步骤排序（如"糖化→酒化→酸化"） |
| `demo-*` | 交互演示容器（第一期：发酵模拟器，见下） |
| `experiment` | 实验卡：材料清单、分步操作、安全提示、观察记录打卡 |
| `vocab` | 术语卡：点击弹出分层解释 |
| `open-question` | 开放提问入口（嵌入提问箱） |
| `related` | 相关知识点/往期链接 |

### 2.4 页面地图

- **首页**：孩子头像选择（哥哥/妹妹）→ 期列表时间线 + 知识地图入口 + 提问箱入口
- **期详情页**：内容块流式渲染，顶部进度，结尾自然导出"延伸问题"引导提问
- **知识地图 v1**：按领域（宇宙/生命/物质/地球/技术…）分组的"星系图"（SVG+动画），知识点是星星，随期数增多而点亮；点击查看分层解释、来源问题、关联知识点
- **提问箱**：孩子自由输入问题（选昵称、可选关联主题）→ 提交后显示"已被家长收到，好问题可能成为下一期主题"
- **家长视图**（隐藏路由）：问题箱整理（解答/转为知识点/标记入下期）、知识点管理、内容检查清单

### 2.5 提问箱的云端收集（已决定上线，闭环必须真实可用）

适配器设计，两种实现都内置、切换即用：
1. **Supabase 免费层**（推荐默认）：一张 `questions` 表 + insert-only 安全策略，前端只需 3 个环境变量，你随时在 Supabase 后台看到孩子的新问题
2. **降级方案**：localStorage 存储 + 一键导出文本（微信发给自己），零配置

### 2.6 游戏化（V1 轻量版）

答对测验得星星、完成一期点亮徽章；进度按孩子档案存在本地（无账号体系，公开站点不采集儿童信息）。

## 三、技术选型与工程结构

- **Vite + Vue3 + TypeScript + Vue Router + Pinia**；样式用原生 CSS + 设计 token（CSS variables），不锁定样式框架
- 知识地图 v1 用 SVG/CSS 动画自绘，不引重依赖；V2 上力导向图时再评估 d3-force
- 内容校验：`scripts/validate-content.mjs`（ajv + JSON Schema），CI 里跑，坏内容进不了构建
- 部署：`vite build` 产物为纯静态，Cloudflare Pages / Netlify / GitHub Pages 任选（我默认按 Cloudflare Pages 给配置），push 即自动发布

```
baike/
├── content/                  # 核心资产（可迁移）
│   ├── issues/001-brewing-vinegar/
│   ├── knowledge/points.json # 知识点库（跨期沉淀）
│   └── schema/               # 各实体 JSON Schema
├── src/
│   ├── blocks/               # 互动内容块组件库
│   ├── views/                # Home / Issue / KnowledgeMap / QuestionBox / Parent
│   ├── stores/               # 孩子档案、进度（Pinia）
│   ├── questionBox/          # 提问箱适配器（supabase / local）
│   └── data/                 # 内容加载、知识图谱构建
└── scripts/validate-content.mjs
```

## 四、内容生产工作流（AI 协作）

1. **选题**：从问题箱挑主题（或你直接指定）→ 我按模板用 AI 产出内容 JSON 草稿
2. **校验**：`npm run validate:content` 自动检查块类型、必填字段、知识点引用、图片资源存在性
3. **预览**：`npm run dev` 你逐块审校（科学性、适龄性、安全提示）
4. **发布**：知识点自动汇入知识地图 → push → 自动上线

## 五、第一期内容方案：「酿酒和酿醋」（发酵）

**主线**：米为什么会变成酒？酒为什么会变成醋？——看不见的小工人（微生物）在干活。

- **引入**：生活中的发酵（酒酿、醋、馒头、酸奶）故事切入
- **核心讲解**：糖化（米→糖，靠曲）→ 酒精发酵（酵母菌，无氧：糖→酒精+二氧化碳）→ 醋酸发酵（醋酸菌，有氧：酒精→醋酸）。两段式发酵是本期的"啊哈时刻"
- **互动演示 `demo-fermentation`**（本期亮点）：
  - 滑块调温度/糖量/时间 → SVG 气泡与气球膨胀动画实时变化，直观感受"酵母吃糖产气"
  - "酒变醋"开关演示：密封 vs 敞口（供氧）导致不同结果
- **家庭实操实验**（安全分级）：
  - 实验A「会吹气球的酵母」：酵母+糖+温水+气球，30 分钟见效，三年级独立可做
  - 实验B「酿一坛酒酿」：糯米+酒曲，家长陪同，3 天观察记录（对照糖化→酒化）；明确提示未成年不饮酒，成品由大人品尝
  - 实验C「酒变醋」：酒酿敞口加醋种，观察酸味与白膜，一周记录
- **测验 + 术语卡**：发酵/酵母菌/醋酸菌/糖化/有氧无氧等，全部带双档解释
- **知识点沉淀**：发酵、微生物、酵母菌、醋酸菌、糖化、酒精发酵、醋酸发酵、灭菌——首批约 8 个知识点点亮知识地图（领域：生命科学/物质科学）
- **延伸问题引导**：泡菜为什么酸？酸奶是亲戚吗？馒头为什么蓬松？→ 自然导向提问箱
